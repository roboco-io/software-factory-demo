# 프로젝트 변경 기록

이 스킬의 기준에 따라 저장소 루트 `CHANGELOG.md`를 관리한다. 작업 내용은 기존 diff, 연결된 이슈·PR, 실제 검증 결과로 확인한다.

## 기록하는 변경

아래 중 하나에 해당하면 기록한다.

- 사용자가 사용할 수 있는 기능·화면·API 동작의 추가, 변경 또는 제거.
- 사용자가 겪는 오류나 운영 장애를 해결하는 수정. 실제 증상과 바뀐 동작을 설명한다.
- 팩토리의 실행·검토·승인·증거·자가 개선·배포·비용 통제 방식의 변화.
- 설정, 권한, 데이터 마이그레이션, 호환성, 보안 또는 라이선스의 변화.
- 저장소 이름·공개 URL·프로젝트 목적·책과의 관계처럼 공개 사용법이나 이해를 바꾸는 문서 변경.
- 새로운 데모 시나리오·진행 가이드 또는 운영 절차. 읽는 사람이 새 행동을 할 수 있거나 기존 행동을 바꿔야 한다면 기록한다.

내부 구조 변경도 사용자·운영자가 알아야 할 동작, 성능, 호환성 또는 운영상의 영향이 있으면 기록한다.

## 제외하는 변경

- 의미와 동작이 같은 오탈자·띄어쓰기·포맷·주석·파일 정리.
- 동작이 바뀌지 않는 리팩터링과 테스트만의 추가·수정.
- 빌드·린트·테스트 재실행, 비용·상태·런 기록의 누적, 봇 상태 라벨 변경.
- 사용자·운영자 영향이 없는 개발 도구 갱신이나 의존성 패치.
- 아직 구현하지 않은 아이디어, 미확인 효과, 계획만 있는 기능.

실험용 실패 주입과 원상복구는 이미 안내된 같은 리허설을 반복하는 경우 실행 기록에 남긴다. 실험 방법이나 실제 검증 장치가 바뀌었으면 그 변화만 CHANGELOG에 기록한다.

## 작성 방식

1. 기록 대상인지 먼저 판단한다. 단순히 커밋이 있다는 이유로 항목을 추가하지 않는다.
2. 아직 통합·배포하지 않은 변경은 `## 미출시 (Unreleased)`에 적는다. 필요한 분류만 사용한다: `추가`, `변경`, `수정`, `보안`, `제거`.
3. 사용자나 운영자의 관점에서 무엇이 바뀌고 어떤 영향을 주는지 한두 문장으로 적는다. 검증된 이슈·PR 링크가 있으면 붙인다. 비밀값과 내부 실행 로그는 쓰지 않는다.
4. 같은 기능의 후속 수정은 기존 미출시 항목에 합친다. 한 PR의 커밋별로 중복 기록하지 않는다.
5. 통합 또는 배포를 확인한 뒤 해당 항목을 실제 날짜의 절로 옮긴다. 이 프로젝트의 날짜는 한국시간 기준이다. 만들어지지 않은 버전·태그·배포 날짜를 추정하지 않는다. 같은 날짜의 절이 있으면 합친다.
6. 다른 작업의 미출시 항목과 과거 근거를 보존한다. 과거 기록을 보충할 때는 확인 가능한 git 이력·PR만 사용하며, 완전한 역사라고 주장하지 않는다.

## 판단 예시

- 도구·모델별 실행 결과를 볼 수 있는 대시보드: 기록한다.
- 승인 대기를 실패로 잘못 보여 주던 화면의 수정: 기록한다.
- 같은 화면을 포맷만 다시 맞춤: 제외한다.
- 책 독자가 데모를 따라갈 수 있는 안내의 신설: 기록한다.
- 비용 합계를 갱신하기 위한 새로운 런: 실행 기록으로 관리하고 제외한다.
- 패키지 패치가 실제 보안 문제를 해결함: 영향과 근거가 확인되면 기록한다.

## 완료 확인

Markdown 링크와 날짜, 미출시·통합 상태, 중복 항목을 확인한다. 프로젝트의 포맷·린트 검사를 수행한다. 이 스킬은 커밋·푸시·병합·배포 권한을 추가로 부여하지 않으며 기존 AGENTS.md와 팩토리 권한 제한을 그대로 따른다.
